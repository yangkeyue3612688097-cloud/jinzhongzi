# 演示视频拍摄手册（8 分钟版 · 可照读）

> 适用：金种子大赛 / 大创结项演示视频
> 环境：本机四件套（前端 5173 / 后端 8080 / 链 8545 / MySQL 3307）
> 特点：**全程真操作、真上链**，每一笔都能在 Hardhat 窗口看到交易；不剪接造假，只剪等待。

## 〇、录制前 40 分钟：准备清单（逐项打勾）

### 1. 启动环境

| 检查项 | 操作 | 通过标准 |
|---|---|---|
| 四件套启动 | 双击工作区根目录 `start-local.bat` | 窗口显示 `ALL READY` |
| 前端可访问 | 浏览器打开 `http://127.0.0.1:5173` | 出现登录页 |

> ⚠️ 若 `start-local.bat` 报端口占用，先关掉旧的四个黑窗口，再双击一次。

### 2. 准备两个干净账号（避免画面里出现测试垃圾数据）

**不要在录像里用 `leader01`**（它的工作台里有我联调时的“冷启动回归测试”等记录）。录制前新注册两个账号：

- 账号 A（创作者/队长）：`demo_lead` / `Demo123456`
- 账号 B（协作者）：`demo_member` / `Demo123456`

注册入口：登录页找“注册”（或 `/login` 页切换）。**提前注册好并各登录一次**，确保能进。

### 3. 准备一个待上传的图片

放到桌面，命名 `demo_art.png`（任意一张 AI 生成图，建议 1024×1024，视觉上像“作品”）。
如果手头没有，用任意图片改名即可，但**解说词不要说“这是 AI 生成的”**，改说“这是一件待存证的 AI 创作作品”。

### 4. 录屏软件与系统设置

- **推荐 OBS Studio**（免费）：场景只捕获浏览器窗口 + 一个终端窗口；输出 1920×1080、30fps、MP4。

## 一、分镜脚本（8 分钟，逐字旁白）

> 每个镜头都标了“点什么按钮 + 说什么”。旁白可以照读，语速慢一点。

### 镜头 1｜开场：项目是什么（0:00–0:40）

**画面**：桌面 → 浏览器全屏打开 `http://127.0.0.1:5173` 登录页。
**操作**：不登录，停在登录页。
**旁白**：
> “这是我们做的 AI 创作可信存证与协作分润系统。它要解决三个问题：AI 作品是谁做的、多人协作收益怎么分、别人凭什么相信这张图没被改过。
> 接下来我用真实操作演示完整流程，所有存证都会真实写入区块链，不是录屏造假。”

### 镜头 2｜注册登录 + 工作台（0:40–1:20）

**操作**：用账号 A 登录 → 进入**工作台**。
**指屏**：鼠标依次划过“我的作品”“协作项目”“我的邀请”“上传作品”。
**旁白**：
> “登录后是创作者工作台。所有作品、协作项目、收到的邀请都在这里。现在我这个账号是干净的，我们从零开始。”

### 镜头 3｜上传作品 + 看到哈希（1:20–2:20）

**操作**：
1. 点 **上传作品**
2. 把 `demo_art.png` **拖进虚线框**（或点“点击选择”）
3. 停顿 2 秒，**鼠标指向页面上显示的 `SHA-256` 哈希**
4. 填“生成参数”（提示词随便写，如 `cyberpunk cat, neon rain`；模型写 `SDXL`）
5. 点 **保存作品**

**旁白**：
> “上传作品的瞬间，浏览器就在本地算出了这个文件的 SHA-256 指纹——注意，这一步不上传原图就已经有指纹了。接着填写生成参数：提示词、模型、种子，这些是证明‘怎么创作出来的’的关键信息。点保存。”

**要点**：一定要让镜头拍到那串哈希字符，这是“存证”的视觉证据。

### 镜头 4｜生成存证 + 链上确认（2:20–3:30）

**操作**：
1. 自动跳转到**作品详情**页
2. 点右下 **生成存证**
3. 等 2–3 秒，页面弹出“存证已写入区块链”
4. **鼠标指向“存证”标签**（显示链上状态）
5. 滚到 **存证记录** 区域展示记录
6. **切到 Hardhat 黑窗口**，指着新出现的一行交易输出（约 3 秒）

**旁白**：
> “点生成存证。系统把作品指纹和创作参数打包，先写入数据库，然后异步提交到区块链。看右边这个黑窗口——这是本地区块链节点，刚刚多了一笔交易，有交易哈希、有区块号。页面上这个标签从‘待确认’变成‘已存证’，说明链上回执已经拿到了。”

**要点**：Hardhat 窗口是全场最有说服力的画面，务必给特写（可以后期放大）。

### 镜头 5｜公开验证（3:30–4:40）★ 评委最想看

**操作**：
1. 在作品详情页点验证入口（跳转到 **存证验证** 页，地址形如 `/verify/0x...`）
2. 页面展示 **三层公开核验**
3. 点 **下载来源清单**（可只点开不下载）
4. 点 **下载存证证书**
5. **关键动作**：在“文件校验”区域把**原图再拖一次**，展示指纹比对一致

**旁白**：
> “现在换一个身份——假设我是买家，我不需要登录，拿到这个哈希就能验证。这一页不需要账号，任何人打开链接都能查。
> 第一层，作品和规范化内容存不存在；第二层，文件指纹对不对——我把原图再拖进来，指纹一致，说明这张图没被改过；第三层，链上状态是不是真的。
> 这里还能下载来源清单和存证证书。”

**要点**：强调“**免登录**”，这是产品的公信力来源。

### 镜头 6｜发起协作 + 对方接受（4:40–6:00）

**操作**（左右双窗口同屏）：
1. 左（账号 A）：回作品详情 → 点 **邀请协作者** → 输入账号 B 的用户名 → 发送
2. 右（账号 B）：进 **我的邀请** → 看到 **收到的协作邀请** → 点接受
3. 左（账号 A）：进 **协作管理**，展示 **协作者列表**
4. 左：在 **协作协议与协商** 里起草协议，比例填 **60 / 40**，提交
5. 左：点确认；右（账号 B）：在自己的协作页点确认
6. 协议状态变为生效，展示 **当前生效的结算依据**

**旁白**：
> “接下来是协作。我邀请另一位创作者加入，她在自己的账号里能看到邀请并接受。
> 然后我们协商分成比例：我 60%，她 40%。注意这里——比例不是系统算的，是我们谈出来的，但谈完必须两个人各自确认，任何一方不点确认，协议就不生效。
> 两边都确认后，协议生效，并且这个版本的协议会锚定上链。以后我们改比例，会生成新版本，**旧版本的收入永远按旧比例分**，不会被追溯。”

**要点**：双窗口同屏是这段的亮点，能直观体现“逐人确认”。

### 镜头 7｜订单 → 收款 → 分账 → 凭证（6:00–7:20）★ 商业闭环

**操作**（账号 A，协作管理页）：
1. 在 **授权订单** 里点下单，金额填 `1000`，买家名填 `BuyerA`
2. 订单状态显示 **待确认收款** → 点确认收款
3. 展示 **收入事件**（金额 1000、协议版本 v1）
4. 点 **分账**（distribute）
5. 展示 **结算凭证** 区域：总额、600/400 分账明细、凭证哈希
6. **再点一次分账** → 弹出“已结算/重复”的拒绝提示

**旁白**：
> “作品授权出去，收到 1000 元。确认收款后，系统生成一条收入事件，并且**记录当时生效的是哪一版协议**。
> 点分账，系统按 60/40 自动拆成 600 和 400，写进各自的收益记录，同时生成一张结算凭证，凭证哈希上链。
> 我再点一次分账——被拒绝了。这是防重复结算，同一笔钱不可能分两次。”

**要点**：“再点一次被拒绝”这个动作一定要拍到，这是工程严谨性的最好证明。

### 镜头 8｜收尾：技术架构 + 边界（7:20–8:00）

**操作**：切到一张提前准备的架构图（或 PPT 一页），或切到 VS Code 展示合约文件。
**旁白**：
> “技术上是这样一条链：Vue 前端 → Spring Boot 后端 → 区块链网关 → 智能合约 → 回执落库。
> 链上只存 32 字节的哈希，原图和参数存在本地，这样既保证不可篡改，又不泄露作品内容。
> 需要说明的是，当前版本的签名身份由平台托管，面向的是创作者个人和小团队；企业级权限体系和监管对接是我们下一步的工作。”

**要点**：主动交代边界，答辩时评委会认为你们“心里有数”，反而加分。

## 二、录制中的 6 个翻车点与应对

| 风险 | 现象 | 应对 |
|---|---|---|
| 存证一直“待确认” | 链窗口没新交易 | 检查 Hardhat 窗口是否还在跑；后端窗口有无报错；重新点一次存证 |
| 邀请发不出去 | 提示用户不存在 | 确认账号 B 已注册且用户名完全一致（区分大小写） |
| 分账提示无权限/无收入 | 订单未确认收款 | 必须先“确认收款”，收入事件生成后才能分账 |
| 页面报 401 | 登录态过期 | 重新登录（视频里可剪掉） |
| 网络请求卡住 | 代理劫持 localhost | 本机代理软件的“绕过本地地址”要勾上；录屏前先手动点一遍确认流畅 |
| 链被重启过 | 旧交易查不到 | 重跑一遍流程即可，**数据库记录仍在**；不要声称“链上永久保存” |

**最重要的一条**：**先完整空跑一遍，再开录**。空跑时把每个按钮位置记住，正式录时一气呵成。如果某一步失败，不要慌，直接重录这一段（后期拼接即可，但同一步骤要保持连续，别跳剪成“假成功”）。

## 三、后期处理建议（30 分钟能做完）

1. **剪掉等待**：每笔链上交易 2–3 秒，可加速到 0.5 秒，但**不要剪掉交易出现的瞬间**
2. **加三处字幕强调**：`SHA-256 指纹`、`链上交易已确认`、`重复分账被拒绝`
3. **片头 3 秒**：项目名 + 一句话定位（用申报书那句）
4. **加一个画中画**：把 Hardhat 交易输出放大到右下角，全程伴随（技术感最强）
5. 导出 1080p MP4，文件名 `AI创作可信存证与分润系统_演示_v1.mp4`
