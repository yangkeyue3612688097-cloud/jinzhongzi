# 项目逆向梳理：能实现什么 / 给谁用 / 哪些是真需求

> 基于当前真实代码与一次端到端验证（ComfyUI 出图 → 自动上链 → 链上回执核验通过）整理。
> 目的：在录测试视频、准备金种子大赛答辩前，先说清楚"项目到底做了什么、哪些是真的、哪些是凑的"。

---

## 〇、一句话结论

**真实跑通的最小闭环**：登录 → 创作（上传图片 **或** ComfyUI 本地出图）→ 一键上链存证 → 任何人凭哈希在公开页验证（看来源清单 / 存证证书 / 链上回执）。

**区块链在本项目里的真实角色**：只做两件事——
1. 把"作品哈希"锚定到一条链（Hardhat 本地链 + BusinessAnchor 合约），证明"某时刻某哈希存在过"；
2. 用**平台托管的私钥**给存证签名（用户并不真正持有私钥）。

**分润的真实角色**：收入事件与结算凭证的**哈希会真实上链锚定**（链上可查凭证存在性、不可抵赖），但**资金的实际分账/打款仍是中心化数据库记账 + 标记"已付款"，链不参与自动转账**。所谓"区块链协作分润"，链保证"凭证不可篡改、可独立核验"，资金结算仍在链下。

## 二、用户定位

### 2.1 设计稿（PPT/申报书）里设想的多角色
- 企业（内容公司、设计工作室、MCN）
- 个人创作者（插画师、AIGC 玩家）
- 监管/版权方（版权局、交易平台、仲裁机构）
- 学生 / 机构（参赛、投资）

### 2.2 代码实际服务的用户（只有两类）
1. **创作者（Creator）**：登录、上传/生成作品、发起协作、查看存证。
2. **协作者（Collaborator）**：被邀请加入协作、接订单、参与分润。

> ⚠️ 没有"企业门户""监管方后台""版权局专用验证通道"——那些是申报书写的，**代码里不存在独立角色门户**。所有人走同一套登录 + 同一套页面，只是权限/协作关系不同。

### 2.3 各人群与痛点（真实 vs 设想）

| 人群 | 真实痛点 | 本项目是否真解决 |
|---|---|---|
| 个人 AIGC 创作者 | 作品被盗用、权属说不清、AI 生成参数无法自证 | ✅ 部分解决：哈希锚定 + 来源清单能证明"某时某参数由我创作" |
| 协作创作的小团队 | 多人贡献比例、分成约定口头化、易纠纷 | 📌 用协作+订单+结算凭证留痕，但分润靠自觉标记已付，无强制力 |
| 企业/外包方 | 批量版权管理、授权链条 | ❌ 未做企业级管理后台，仅个人视角 |
| 监管/买家/平台（第三方验证） | 想独立验证真伪，不 trusting 平台自说 | ✅ 公开验证页可做（但链是本地链，下面细说局限） |
| 投资/评委（金种子大赛） | 看技术含金量与落地性 | ⚠️ 见第四节与答辩建议 |

## 三、原始业务需求：刚需 vs 凑技术点

### 3.1 刚需真实需求（真痛点）
1. **AIGC 作品权属证明**：AI 生成内容权属模糊、易被盗用。需要"某个时间点、由某人、用某参数创作"的可信留痕。这是 2024–2026 年 AIGC 版权圈的真实痛点。
2. **创作过程可自证**：存"来源清单 + 生成参数"，比只存一张图更有说服力（能反驳"这是抄的"）。
3. **对外公开验证**：买家/平台/仲裁方能**不依赖平台**核验真伪——这是存证类产品的核心价值。
4. **协作留痕**：多人合作的贡献与分成约定有可信记录，减少纠纷。

### 3.2 为堆技术点硬加的功能（凑的）
1. **"链上分润"叙事**：分润实际是数据库记账 + `mark-paid`，没有智能合约 escrow、没有稳定币自动打款。叫"区块链分润"名不副实。
2. **用"公链"做存证**：本项目用 **Hardhat 本地链**，链可随时重置，**严格说不算"可信第三方"**——真正的可信存证应接以太坊/司法链/公信链。本地链只适合演示。
3. **平台托管私钥却同时做"钱包绑定"**：`attest-identity`（平台用 `IDENTITY_SECRET` 派生密钥代持）与 `update-wallet`（让用户绑自己的钱包）**逻辑冲突**——既代持又让用户自主，叙事混乱。
4. **ComfyUI 被包装成"AI 可信能力"**：ComfyUI 只是调用开源模型出图，和"可信"无必然关系；它演示的是"AI 生成"，不是"AI 可信"。
5. **企业/监管多角色门户**：申报书有，代码无，属 PPT 需求。

## 四、需求分层（核心 / 次要 / 伪需求）

### ✅ 核心（必须有，没有项目就不成立）
| 功能 | 代码是否真实现 | 说明 |
|---|---|---|
| 用户登录 + 链上身份绑定（attest-identity） | ✅ | 平台托管私钥签名，存证由此签名 |
| 作品创建（上传 / ComfyUI 出图） | ✅ | 主流程两种入口都通 |
| 计算哈希 + 上链存证（evidence） | ✅ | 已验证返回真实 txHash/区块 |
| 公开验证页（凭哈希查真伪 / 清单 / 证书） | ✅ | 无需登录，第三方价值所在 |

> 这四件事构成了"**可信存证**"最小闭环。没有它们，项目就是空壳。录视频时这条主线必须完整展示。

### 📌 次要（锦上添花，有更好，没有不影响主流程）
| 功能 | 代码是否真实现 | 说明 |
|---|---|---|
| 来源清单 manifest / 存证证书 certificate 下载 | ✅ | 验证的增强展示，提升说服力 |
| ComfyUI 本地 AI 出图 | ✅ | 展示 AI 能力，但"上传图片"也能完成主流程 |
| 作品版本管理 WorkVersion | ✅ | 同一作品多版本留痕 |
| 协作协议 / 邀请 | ✅ | 协作前的约定留痕 |
| 统计仪表盘 | ✅ | 数据看板 |
| 操作日志 | ✅ | 审计辅助 |

### ❌ 伪需求（为堆区块链/AI 硬加，实际没人这么用）
| 功能 | 代码是否真实现 | 问题 |
|---|---|---|
| "链上协作分润 / 自动分账" | ❌（只是数据库记账） | 链没参与分钱，命名误导 |
| 本地 Hardhat 链当"可信存证"对外宣称 | ⚠️ 能跑但不可信 | 链可重置，非第三方公信 |
| 用户自主钱包 + 平台托管私钥 并存 | ⚠️ 两接口都在 | 身份模型自相矛盾 |
| 企业/监管专属门户 | ❌ | PPT 需求，未落地 |
| 把"调用开源 ComfyUI"当作核心技术壁垒 | ❌ | 非自研，无壁垒 |

## 五、给金种子大赛答辩的策略

**重点讲（真实、可演示、有亮点）**
- 端到端闭环：创作 → 哈希 → 平台签名 → 上链 → 公开验证，一键完成，已实测。
- "来源清单 + 生成参数"比单纯存图更有版权说服力。
- 公开验证页：第三方无需登录即可核验，体现"可信"而非"自证"。

**淡化 / 谨慎讲（避免被评委追问翻车）**
- "区块链分润"：建议改为"协作分润留痕（链上确权 + 链下结算）"，别说是智能合约自动分账。
- "我们用的是公链"：如实说是本地测试链演示，可补充"生产可切换以太坊/司法链"的规划。
- 钱包与托管私钥冲突：答辩前二选一统一口径（建议统一为"平台托管签名，降低用户门槛"，并说明未来可升级自托管）。

**建议补强（若有时间，提升含金量）**
1. 把"上链"切换到一条**真实可读的链/司法链/公信力接口**，哪怕测试网，也比本地链可信。
2. 分润真正用一笔智能合约 escrow 做"订单确认即锁资、验收即放款"，让"分润"名实相符。
3. 身份模型二选一：要么纯托管（去掉钱包绑定），要么纯自托管（用户签名上链），消除矛盾。
4. 加一个"监管/买家视角的只读验证入口"截图，呼应多角色叙事。
