## 2. 部署

### 2.1 Remix 路线（演示用，10 分钟）

1. 打开 https://remix.ethereum.org → 新建文件 → 粘 `AICreationSystem_Remix.sol`
2. 编译器 **0.8.24**，`EVM Version` 选 **paris**（不选 paris 在部分链上会因 PUSH0 报错）
3. 部署**两个**合约，顺序不能反：

| 步骤 | 合约 | 构造参数 |
|---|---|---|
| ① | `AICreationEvidence` | `_admin`=平台管理员地址 `_arbiter`=仲裁员地址 |
| ② | `AICreationProfitSplit` | `evidenceAddr`=①的地址 `_admin`、`_arbiter`、`_platformWallet`=平台收款地址 |

`admin` 与 `arbiter` 建议不同地址——仲裁要能独立于运营，这是"四权分离"里最容易被评委注意的一点。

### 2.2 部署后必须做的 3 件事

```solidity
// 1. 授权分润合约改作品状态（不做这步，作品永远停在 Finalized，settle 不会报错但状态不流转）
evidence.setSettler(分润合约地址, true);

// 2. 指定链下评分服务地址（不设则只有 admin 能 lockShares）
split.setScorer(评分服务地址);

// 3. 核对参数（默认值已符合申请书：W1=0.55 / W2=0.25 / W3=0.20，平台费 5%，异议期 3 天）
split.params();
```

> 第 1 步是旧版 v0.1 跑不通的根因：旧合约在分润末尾直接调 `evidence.setWorkStatus`，但分润合约不是 admin，`onlyAdmin` 必 revert。现在改成了 `isSettler` 白名单 + `try/catch`，即使漏配也不阻塞分账（资金安全优先）。

## 3. 一次完整业务：谁在什么时候调什么

| # | 调用方 | 方法 | 参数 | 前置条件 |
|---|---|---|---|---|
| 1 | 创意发起者 | `evidence.createWork(inputRoot, metadataURI)` | 提示词+意图的哈希；链下元数据 URI | 无。创作者自动登记为 `Ideator` 并视为已接受 |
| 2 | 发起者 | `evidence.addContributor(workId, addr, role)` | role 见 §4.1 | `Draft` |
| 3 | 被邀请人 | `evidence.acceptRole(workId)` | — | 已被登记。**不确认就不能追加证据**，防"被挂名分钱" |
| 4 | 各协作者 | `evidence.addEvidence(workId, etype, dataHash, uri)` | etype 见 §4.2 | 已 `acceptRole`，`Draft` |
| 5 | 发起者 | `evidence.finalizeWork(workId, resultHash, uri)` | 成品哈希 | `Draft`，会写入 `Final` 证据并封链 |
| 6 | 评分服务 | `split.lockShares(workId, scores[], sheetHash)` | 七项指标 + 明细 JSON 哈希 | `Finalized`。**CI 在链上复算**，调用方不能直接传比例 |
| 7 | 各协作者 | `split.consentShares(workId)` | — | 份额已锁定。全员确认可跳过 3 天异议期 |
| 8 | 任何人 | `split.depositRevenue(workId)`（带 `value`） | — | 作品存在。**纠纷期间也能入账**，不会让买家付款失败 |
| 9 | 任何人 | `split.settle(workId)` | — | 已锁定 + 无待处理异议 + （全员确认 或 异议期已过） |
| 10 | 收款人 | `split.withdraw()` | — | 有待领取余额。Pull 模式，谁提谁付 gas |

第 5→6 之间不允许再追加证据（`addEvidence` 检查 `Draft`）；第 9 步可以**重复执行**，这是"版税"而不是"一次性结清"——第二轮授权收入进来再 `depositRevenue` + `settle` 即可，`settleRound` 自增。

## 4. 参数怎么填

### 4.1 Role 枚举

| 值 | 含义 |
|---|---|
| 0 | None（未登记） |
| 1 | Ideator 创意发起者 |
| 2 | PromptDesigner 提示词设计者 |
| 3 | ModelProvider 模型/技术提供方 |
| 4 | Generator 生成执行者 |
| 5 | Editor 后期编辑者 |
| 6 | Operator 运营推广者 |

### 4.2 EvidenceType 枚举

| 值 | 含义 | 对应证据原文 |
|---|---|---|
| 0 | Prompt | 提示词全文（含负向词） |
| 1 | Parameter | 模型名、seed、steps、CFG、尺寸、采样器、scheduler |
| 2 | Generation | AI 生成的中间图 |
| 3 | Edit | 人工迭代版本（PSD / 蒙版 / 修改说明） |
| 4 | Final | 最终成品（只能由 `finalizeWork` 写入） |

### 4.3 ScoreInput 七项（容易填错的地方）

```
s11, s12, s21, s22, s3  →  0~10000     表示 0~100 分，1 分 = 100
alpha, lambda           →  0~10000     表示 0~1 的系数，1.0 = 10000
```

**这里最容易错**：得分和系数都是 1e4 定点，但语义不同。把 `alpha=1.0` 填成 `100` 会导致贡献指数几乎归零，分账比例看起来像"随机数"。前端建议做两个输入控件：分数输入 0~100（内部 ×100），系数输入 0~1（内部 ×10000）。

### 4.4 一个实测算例（1 ETH、4 人、平台费 5%）

| 角色 | CI | 比例 | 实得 |
|---|---|---|---|
| 创意发起 | 76.11 | 26.18% | 0.2488 |
| 提示词设计 | 89.24 | 30.70% | 0.2917 |
| 后期编辑 | 66.51 | 22.88% | 0.2174 |
| 运营推广 | 58.81 | 20.23% | 0.1922 |

平台费 0.05 + 分配合计 0.95 = 1.00，**一 wei 不差**（整除尘埃补给最大贡献者）。

## 5. 常见 revert 对照

| 错误名 | 真正的意思 | 怎么改 |
|---|---|---|
| `NotSettler` | 分润合约没被授权 | `evidence.setSettler(split, true)` |
| `NotScorer` | 调用者不是评分服务也不是 admin | `split.setScorer(addr)` |
| `RoleNotAccepted` | 协作者还没 `acceptRole` | 让本人先确认 |
| `InvalidStatus` | 状态不对（如在 `Finalized` 后追加证据） | 检查 `getWork(workId).status` |
| `SheetAlreadyLocked` | 已产生过结算，份额表冻结 | 份额表在**首次结算前**可改（version+1），结算后永久冻结 |
| `ObjectionWindowOpen` | 异议期未过且未全员确认 | 等 3 天，或让所有协作者 `consentShares` |
| `ObjectionPending` | 有人提了异议，等仲裁 | `resolveObjection(workId, true)` 驳回后可结算 |
| `NothingToSettle` | 托管里没余额 | 先 `depositRevenue` |
| `ScoreOutOfRange` / `FactorOutOfRange` | 分数或系数超过 10000 | 见 §4.3 |
| `ZeroTotalContribution` | 所有人 CI 都是 0 | 至少一个人有有效得分 |
| `ContractPaused` | 紧急暂停中 | admin `unpause()` |

## 7. 录屏脚本（3 分钟，答辩现场可复现）

```bash
npx hardhat run scripts/demo-e2e.js
```

依次输出：建作品 → 登记 3 个协作者 → 全部确认 → 追加提示词/参数/生成/编辑证据 → 定稿 → 打乱顺序校验链完整性 → 评分引擎算 CI → 锁份额 → 全员确认 → 入金 → 结算 → 提现。

要强调的两个动作：
1. `verifyChain` 在校验前**故意调换两条证据的哈希**，返回 `ok=false` 和断点下标——这是"真时序链"和"哈希堆叠"的区别。
2. 同一个订单**重复结算被拦截**，但**新收入可以再次结算**——版税模型。

## 8. 给同学的 5 句话

1. 部署完**先**调 `evidence.setSettler(分润地址, true)`，否则状态不流转。
2. 哈希统一走 `scripts/hash-utils.js`：JSON 必须先递归排序 key，否则 `verifyEvidence` 永远 false。
3. `ScoreInput` 里分数是 0~10000 表示 0~100 分，系数是 0~10000 表示 0~1，别混。
4. 金额全部用 `BigInt` / `uint256`，前端不要过 `Number`（0.1 ETH = 1e17，超 JS 安全整数）。
5. `package.json` 里 Hardhat 锁死 `2.19.5`（精确版本，不能带 `^`）——2.22 的 EDR 原生模块在 Windows 上加载失败，已踩过。

## 9. 已知边界（主动说，比被问出来强）

- **链还是本地/Polygon 测试网**，FISCO BCOS 合作方的合约还没到，跨链适配属下一阶段。
- **评分是规则引擎 + 平台上链**，不是去信任评分。真正的去信任要做 EIP-712 协作者联签，已预留 `sheetHash` 作为联签对象。
- **收款是人工确认**（`depositRevenue` 由平台代调），没接支付通道。
- **合约只保证"记录不可改"，不保证"生成时真的用了这些权重"**——后者需要 TEE 远程证明。
- `MAX_CONTRIBUTORS=20`、`MAX_EVIDENCE_PER_WORK=300` 是防 Gas 攻击的硬上限，超过请走 Merkle 批量锚定（申请书已规划）。
