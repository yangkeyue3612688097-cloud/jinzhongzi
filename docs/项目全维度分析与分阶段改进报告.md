## 〇、结论先行（三句话）

1. **功能面不简陋，逻辑链完整**：确权存证 → 协作分账 → 公开验真这条主线是真正端到端跑通的（视频已逐环节证明），不是 PPT 空壳。
2. **"简陋"体现在三处**：① UI 是典型 Element Plus 后台模板风，能用但无品牌、无细节打磨；② 工程化弱（本地内存链、平台托管私钥、无部署脚本、无测试覆盖）；③ 少数"技术点"是堆砌未接线（合约自动分润、模型指纹、贡献量化）。
3. **离"可交付产品"还差一个工程化版本（v1）**，离"可信存证"的对外承诺还差一条真实链/司法链。

## 一、项目定义

### 1.1 一句话定义

面向 **AI 创作者个人 + 2~5 人小微协作团队** 的可信存证与分润系统：把 AI 作品的**生成过程参数**（提示词/模型/种子）签名后锚定上链形成不可篡改证据链；多人协作的分成比例**逐人确认、版本化固化**；作品授权收入**按生效协议自动分账**并出具可公开核验的结算凭证。

### 1.2 完整定义（五个维度）

| 维度       | 定义                                                        |
| -------- | --------------------------------------------------------- |
| **做什么**  | AI 创作「确权存证 + 协作分润 + 公开验真」一站式工具                            |
| **给谁用**  | 个人 AI 创作者、2~5 人接单小微团队、买家/公众（免登录验证方）                       |
| **解决什么** | 确权难（AI 生成过程无法自证）、分账乱（口头约定易纠纷）、验真难（第三方无法核验来源）              |
| **技术边界** | 业务平台做体验，区块链做「哈希锚定 + 托管签名」，链上只存 32 字节哈希，原文在 MySQL + 本地文件系统 |
| **现状定位** | 可现场演示的**最小可信闭环**（Demo 级），非生产级 SaaS                        |

### 1.3 核心叙事（答辩主推）

"存的不只是一张图，而是**生成过程的出生证明**：用什么模型、什么提示词、什么种子、谁在什么时候提交——全部签名上链，任何人都能凭哈希独立核验，改一像素都验不过。"

## 五、功能是否"过于简陋"——分层判定

### 5.1 结论：**功能不简陋，产品化程度简陋**

"简陋"不在功能数量（13 项主线功能齐全），而在以下三个层面：

**① UI/UX 简陋（演示级，非产品级）**

- 全站是 Element Plus 默认后台模板风：紫渐变登录页 + 白底卡片 + 表格 + 弹窗，无品牌 VI、无动效、无空状态/加载态设计。
- 公开验证页（核心价值页）信息堆叠密集，三层核验没有清晰的视觉层级，第三方用户理解成本偏高。
- 缺失：消息通知（邀请/待确认/到账全靠手动刷新）、移动端适配（有 mobile 设计稿但前端未做响应式）、无障碍。

**② 工程化简陋（能跑，不能交付）**

- 链是 **Hardhat 本地内存链**，重启清空 → 演示必须"一链到底"或重锚，不能对外宣称"链上永久保存"。
- 私钥明文落 `.env`、平台托管代签（非用户自持），`update-wallet` 接口返回 success 但实际不生效。
- 无 CI/CD、无 Docker、无生产部署脚本、无单元/集成测试覆盖（仅 3 个后端测试类 + 合约 11 项测试）。
- 异常/越权审计不系统：`JwtInterceptor` 只认证不鉴权，敏感操作靠各 Service 自查。

**③ 技术叙事与实现有落差（对评委可能翻车）**

- "区块链分润"名不副实：分账是数据库记账，链只锚定凭证哈希。
- "时序哈希链"只存在于未启用的 `AICreationEvidence.sol`，主线 `BusinessAnchor.sol` 是独立锚定无链式结构。
- "模型指纹" 18 项自测通过但后端 0 引用。

## 六、需要改进的功能（按优先级）

### P0（不做会翻车 / 主流程有断点）

1. **换一条真实可读的链或至少测试网**——本地内存链无法支撑"可信第三方"叙事，是最大硬伤。
